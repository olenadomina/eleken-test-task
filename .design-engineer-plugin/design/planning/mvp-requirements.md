# MVP requirements (prototype scope)

Sources: Eleken brief (Part 1, Part 2, "States and edge cases"); submitted Figma file tcraZAiMnwIP7IZUSjI3V2.

## Must-have – from the brief, Part 2 (Homework Review Queue)

Fields (verbatim): "Submission / task name, student, course or module, submission date, review status, reviewer, priority or overdue indicator, last activity, actions".

Filters (verbatim): "Review status, course or module, reviewer, submission date, student, needs attention / overdue".

Goal actions (verbatim): "browse submissions, filter and prioritize work, open submission details, update review status, leave comments, and handle bulk actions when relevant."

States (verbatim): "empty, no results, loading, error, read-only."

Edge cases (at least 2–3, verbatim list): "long names, many selected items, many filter options, long comments, overflow, or partial failure on a bulk action."

## Must-have – Part 1 (2 redesigned screens)

- Learner dashboard: what needs attention this week, continue learning in 1 click, course progress, live class with Join, role switch.
- Create Event: basics, date & time with time zone, repeat with a schedule summary, linked courses, price, password, materials, publish with a draft status and a learner preview.

## Prototype-specific requirement (01.10.2026)

A fully tappable product where every screen of the submitted design is interactive and navigation does not dead-end. The exact screen list is approved in information-architecture.md.

## Not in scope (deferred in Notes)

Rubric grading, inline PDF annotation, saved review-queue views and custom columns, configurable review deadline, reviewer workload analytics.

Mobile layouts were initially deferred. The later approved HTML prototype adapts to phones; the Figma submission remains desktop. The report result has its own working column selector.
